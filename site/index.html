What it does

Everything a retail back-office needs

Three domains, cleanly separated: point-of-sale & inventory, customer lifecycle & recovery, and a secure integration API.

Sales & Inventory

  • Product catalog — SKU, price, per-branch stock
  • Point of sale with automatic stock deduction
  • Overselling is impossible — atomic transactions, row locks & a DB CHECK
  • Race-safe invoice numbering + PDF invoices

Customer CRM

  • Purchase history — frequency & last-purchase
  • Lost-customer detection (configurable threshold)
  • Assign lost customers to employees (admin-only)
  • Idempotent KPI credit when a customer is won back
  • Re-engagement campaigns — email + SMS

Bonus & Integration

  • Multi-branch — locations, stock & sales per branch
  • Auto-emailed PDF invoices after each sale
  • Secure e-commerce product feed API
  • Token ability + dedicated rate limit

How it's built

Engineered for correctness

Data-integrity operations are synchronous and transactional; side effects are asynchronous and queued after commit.

🔒 Overselling is provably impossible

Each sale runs in one transaction that locks every inventory row (SELECT … FOR UPDATE, ordered to avoid deadlocks), validates all lines before mutating, and is backstopped by a database CHECK (quantity ≥ 0).

📒 Ledger-backed, rebuildable counters

Stock, KPI scores and customer aggregates are caches of append-only ledgers (stock_movements, kpi_events) — reconstructable at any time with a single artisan command.

⚡ Async fan-out after commit

A committed sale dispatches SaleCompleted to queued listeners that update stats, credit recovery KPI, and email the PDF invoice — a rolled-back sale dispatches nothing.

🧪 Verified under real concurrency

A 16-test Pest suite on MySQL — including a flagship test that races two real OS processes for the last unit — proves exactly one sale wins and stock never goes negative.

Technology

The stack

A domain-sliced modular monolith on the backend, a feature-sliced SPA on the frontend, one docker compose up away.

Backend

Laravel 13 (PHP 8.3) · Sanctum cookie auth · spatie/permission RBAC · domain-driven Actions, Services, Events & Policies · dompdf invoices.

Frontend

React 19 + TypeScript · Vite · TanStack Query · Zustand · React Hook Form + Zod · Tailwind. Cache-invalidation drives live updates.

Infrastructure

Docker Compose — nginx, PHP-FPM, queue worker, scheduler, MySQL 8, Redis, Mailpit (SMTP) and the Vite dev server.

Try it

Run the full app locally

The live application is a Dockerized API + SPA. Clone the repo and bring the whole stack up in three commands.

# 1 · create the env files the containers read
cp .env.example .env
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env

# 2 · build & start everything (installs deps, generates APP_KEY)
docker compose up -d --build

# 3 · create the schema and load realistic sample data
docker compose exec app php artisan migrate --seed

# then open:  SPA http://localhost:5173  ·  API http://localhost:8000  ·  Mail http://localhost:8025
# sign in:    admin@salescrm.test  /  password
